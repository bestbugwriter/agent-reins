# UI 验收：与参考原型截图对比

## 准备
- **参考物**：brainstorming 阶段的 HTML 原型、设计稿或用户给的截图。没有参考物时先问用户要，不要凭描述自行判断"差不多"。
- **截图工具**（按可用性选一种）：Chrome DevTools MCP、Playwright MCP、`npx playwright screenshot`、其他能截图的浏览器自动化工具。
- **固定视口**：至少 `1440x900` 和 `390x844`。截图前等待动画结束，参考图和实现图的尺寸必须一致。

## 实现时
- 原型是 HTML 时，直接复用原型的结构、class 和 CSS 数值，不要根据文字描述重新实现一遍。
- 只用项目已有的设计 token 和组件；原型中的值和 token 不一致时，记下来问用户。

## 对比循环（最多 3 轮）
1. 对每个"状态 × 视口"分别截取参考图和实现图。
2. 输出差异表：

| 状态 | 视口 | 元素 | 期望 | 实际 | 修复 |
|---|---|---|---|---|---|

3. 只修复差异表中列出的问题，不顺手调整其他样式。
4. 保留"当前最好的一版"。新一轮必须在功能正常的前提下差异更少，才能替换它，不要默认交付最后一轮。
5. 差异表清空或 3 轮用完即停止。

## 完成报告必须包含
- 每个状态和视口的实现截图路径（放在 `.scratch/reports/ui-verify/`），以及对应的参考图。
- 控制台无报错的检查结果。
- 仍未对齐的项目及原因。不得省略，也不得写"基本一致"。

## 禁止
- 只凭编译通过、单测通过或"代码看起来对"就宣布 UI 完成。
- 发现差异后修改参考图来迁就实现。
