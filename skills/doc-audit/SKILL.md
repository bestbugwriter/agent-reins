# 文档审计：找出该删、该改的文档

## 1. 盘点
- 列出入库的文档：`git ls-files '*.md' '*.mdx' '*.rst'`，统计每个目录的文件数和行数。
- 找出带大段代码块的文档：`git ls-files '*.md' | xargs grep -l '^```'`。

## 2. 分类（每个文档只归一类）
| 类别 | 判定 | 建议 |
|---|---|---|
| 过程产物 | 计划、任务清单、验证报告、评审记录、交接、日志、已归档的 change | 删除 |
| 重复 | 与其他文档或代码注释重复 | 合并到一处，删除其余 |
| 过期 | 引用的文件、符号、配置已不存在，或描述与代码行为不符 | 修正或删除 |
| 嵌入代码 | 大段复制的代码 | 改为 `路径#符号` 引用 |
| 有效 | 只记录代码中看不出来的原因、约束、坑 | 保留 |

判定"过期"必须实际核实：检查引用的路径和符号是否存在（例如 `git ls-files`、CodeGraph、grep）。不能只看文件修改时间。

## 3. 外部链接
- 有 `lychee` 时运行 `lychee --no-progress --format markdown <文件...>`；没有时用 `curl -sIL -o /dev/null -w '%{http_code}' <url>` 抽查。
- 列出失效链接、重定向链接；可以改为带版本号的稳定地址的，给出建议。

## 4. 输出
- 写一个单文件 HTML 报告到 `.scratch/doc-audit.html`：总览数字、按类别分组的清单、每项的证据和建议操作。
- 在对话里只给摘要和报告路径。
- **用户确认后**再执行删除或修改，并且删改与其他改动分开提交。

## 禁止
- 未经确认直接删除文档。
- 为审计结果再新建入库文档。
