# 文档审计：找出该删、该改的文档

## 1. 盘点
- 列出入库的文档：`git ls-files '*.md' '*.mdx' '*.rst'`，按目录统计文件数和行数。
- 找出带大段代码块的文档：`git ls-files '*.md' | xargs grep -l '^```'`。
- 先读项目的 AGENTS.md / CLAUDE.md 和流程配置，确认哪些目录是项目约定要保留的（例如 OpenSpec 的 `openspec/specs/`、`openspec/changes/archive/`，ADR 目录）。

## 2. 分类（每个文档只归一类）
| 类别 | 判定 | 建议 |
|---|---|---|
| 过程产物 | 计划、任务清单、验证报告、评审记录、交接、日志 | 删除；位于项目约定保留的目录时按约定保留，只建议精简 |
| 重复 | 与其他文档或代码注释重复 | 合并到一处，删除其余 |
| 引用失效 | 引用的文件、符号、配置已不存在 | 修正或删除 |
| 与代码矛盾 | 描述的默认值、限制、流程、枚举与代码不符 | 以代码为准修正；怀疑代码有误时列为待用户确认 |
| 嵌入代码 | 大段复制的代码 | 改为 `路径#符号` 引用 |
| 有效 | 只记录代码中看不出来的原因、约束、坑 | 保留 |

判定"引用失效"或"与代码矛盾"必须有证据：检查路径和符号是否存在（`git ls-files`、CodeGraph、`git grep -w`），抽查文档中的具体数值和枚举与代码是否一致。不能只看文件修改时间。

## 3. 注释
- 抽查注释里提到的函数名、参数名、配置项是否还存在。
- 找出指向已不存在代码的 TODO/FIXME，以及复述代码、已经和代码不一致的注释。

## 4. 外部链接
- 有 `lychee` 时运行 `lychee --no-progress --format markdown <文件...>`；没有时用 `curl -sIL -o /dev/null -w '%{http_code}' <url>` 抽查。
- 列出失效和重定向的链接；能改为带版本号的稳定地址的，给出建议。

## 5. 输出
- 写一个单文件 HTML 报告到 `.scratch/reports/doc-audit.html`：总览数字、按类别分组的清单、每项的证据和建议操作。
- 在对话里只给摘要和报告路径。
- **用户确认后**再执行删除或修改，并与其他改动分开提交。

## 禁止
- 未经确认直接删除文档。
- 为审计结果再新建入库文档。
